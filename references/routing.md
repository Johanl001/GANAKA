# Routing Table — System Assignment by Job

| Job | Primary system | Secondary system | Status |
|-----|---------------|------------------|--------|
| Natal reading | KP | BPHS | Hypothesis, untested |
| Event timing | BPHS or Phaladeepika | KP | Hypothesis, untested |
| Event promise (yes or no) | Not chosen yet | Not chosen yet | Open |

For every question the skill runs all active systems and logs each prediction separately, with a system field. KP and Parashari use different ayanamsa and house settings, so their windows will sometimes differ. Those differences are data.

The combination rule is fixed before testing. Starting rule: the combined window is the overlap of the individual windows. If they do not overlap, the skill reports that the systems disagree and gives no combined prediction. A combined prediction is logged as its own system, COMBINED.

The test of the combining idea is whether COMBINED beats the best single system on the same events. Window length is scored next to hit rate, because a wider window is easier to hit.
